1. OBJETIVO
--------------------------------------------------------------------------------
Predecir el comportamiento de compra de clientes de Instacart utilizando un
pipeline hibrido de Machine Learning con clustering + modelos de clasificacion
y regresion, diferenciado por cluster de usuario.

2. DATASET
--------------------------------------------------------------------------------
Fuente: Kaggle - Instacart Market Basket Analysis
  - orders.csv:              3,421,083 pedidos
  - order_products__prior.csv: 32,434,489 pares producto-orden
  - order_products__train.csv:  1,384,617 productos en train
  - products.csv:               49,688 productos
  - aisles.csv:                   134 pasillos
  - departments.csv:                21 departamentos

Dataset final: 131,209 registros (train orders), 38 columnas
Usuarios unicos: 206,209

3. ARQUITECTURA DEL MODELO
--------------------------------------------------------------------------------

  FASE 1: Feature Engineering (caracteristicas_mejorado.py)
  ─────────────────────────────────────────────────────────
  Se construyen 34 features organizadas en 6 categorias:

  A) Temporal del pedido actual (7 features)
     - hour_sin, hour_cos (ciclico 24h)
     - dow_sin, dow_cos (ciclico 7d)
     - es_finde (sabado/domingo)
     - es_horario_laboral (9am-5pm)
     - es_noche (7pm-5am)

  B) Carrito actual (6 features)
     - total_productos, productos_recomprados, ratio_recompra
     - avg_product_popularity (popularidad promedio de productos en carrito)
     - avg_product_reorder_rate (tasa de recompra promedio de productos)
     - max_product_popularity (producto mas popular del carrito)

  C) Derivadas del carrito (3 features)
     - cart_vs_avg (tamano actual / promedio usuario)
     - order_number_norm (posicion en vida del usuario)
     - es_primera_compra

  D) Interacciones carrito x usuario (4 features)
     - cart_x_recompra (total_productos * ratio_recompra)
     - cart_x_dept (total_productos * promedio_dept_usuario)
     - std_x_tendencia (std_dias_espera * tendencia_dias)
     - recompra_x_std (promedio_recompra_usuario * std_carrito)

  E) Lifecycle y tendencia (3 features)
     - lifecycle_pos (order_number / total_pedidos_historicos)
     - es_pedido_reciente (ultimos 2 pedidos)
     - densidad_compra (productos unicos / total_pedidos)

  F) Perfil historico del usuario (11 features)
     - promedio_dias_espera, std_dias_espera, total_pedidos_historicos
     - tendencia_dias (ultimo pedido vs promedio historico)
     - promedio_productos, std_carrito, promedio_recompra_usuario
     - promedio_dept_usuario, n_departamentos_historial
     - n_aisles_historial, n_products_historial

  FASE 2: Clustering (K-Means, 3 clusters)
  ─────────────────────────────────────────
  Features de clustering (10):
    promedio_dias_espera, std_dias_espera, total_pedidos_historicos,
    promedio_productos, promedio_recompra_usuario, promedio_dept_usuario,
    std_carrito, n_departamentos_historial, n_aisles_historial, tendencia_dias

  Clusters resultantes:
    C2 - ESTABLE:  35,812 registros (usuarios con patron regular)
    C0 - REGULAR:  39,513 registros (usuarios intermedios)
    C1 - CAOTICO:  55,041 registros (usuarios impredecibles)

  FASE 3: Modelos de ML
  ─────────────────────
  Se entrenan 3 modelos por cluster y por tarea:

  V1 - Clasificacion: "El pedido es en <=7 dias?"
    - XGBoostClassifier (Optuna, 15 trials)
    - CatBoostClassifier (auto_class_weights='Balanced')
    - LGBMClassifier (is_unbalance=True)
    - Stacking: promedio de probabilidades de los 3 modelos

  V4 - Regresion: "Cuantos productos comprara?"
    - XGBRegressor (Optuna, 15 trials)
    - CatBoostRegressor
    - LGBMRegressor

  Validacion: GroupKFold (3-fold para Optuna, 3-fold para evaluacion final)
  Los folds respetan la agrupacion por user_id para evitar leakage temporal.

  FASE 4: Feature Selection
  ─────────────────────────
  Se eliminan features con correlacion < 0.01 con el target:
    V1 elimina: hour_sin, avg_product_popularity, max_product_popularity,
                promedio_dept_usuario (4 features)
    V4 elimina: hour_sin, hour_cos, es_finde, es_horario_laboral,
                es_noche (5 features)

  FASE 5: Optimizacion de Umbral
  ───────────────────────────────
  Para V1 se prueba umbrales de 0.30 a 0.50 y se selecciona el que
  maximiza F1-Score de clase positiva (pedido en 7d).

  Stacking inteligente: si el ensemble no supera al mejor modelo individual,
  se usa el mejor individual.

9. LIMITACIONES Y RECOMENDACIONES
──────────────────────────────────
  - El F1 del cluster CAOTICO (35.9%) es bajo porque estos usuarios
    no tienen patron predecible. Solo scoring, no campanas agresivas.
  - El cluster REGULAR (F1=50.2%) responde bien a CatBoost. Usar
    score de propension en vez de clasificacion binaria.
  - El cluster ESTABLE (F1=70.6%) es el mas predecible. Campana
    agresiva con umbral 0.30.
  - Las features de popularidad de producto fueron las que mas
    subieron V4 (R2 +35-64%).
  - El techo teorico de correlacion es ~0.44, y ya estamos en
    R2=0.54 con CatBoost, lo cual es un resultado fuerte.
